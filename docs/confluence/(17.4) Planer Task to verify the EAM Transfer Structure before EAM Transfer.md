# \(17\.4\) Planer Task to verify the EAM Transfer Structure before EAM Transfer

## General

|  |  |
| --- | --- |
| **User Story** | As a Planer I want to receive a task before the device is transferred to the EAM, in case the EAM Structure is not correct /  not defined as expected, so I'm able to correct the structure in EAM before transferring the data. |
| **JIRA** | Update 19.02.: - Logical adaption of displayed expected structure depending on DigiONS / other process types:  - Additional label adaptions:  |
| **Description** | In the last step of the DigiONS / Retrofit process, the necessary information is transferred to the EAM system ([(17) Transfer to EAM](https://eon-energy.atlassian.net/wiki/spaces/kfwt22/pages/880247612/17+Transfer+to+EAM)).Before this transfer to EAM, the system must check whether the TP and the expected structure to insert the equipments are available as expected. Additionally, the system must verify if more than one equipment is stored directly under the TP (not only under the expected structure).In case one of these validations fail, a new Planer task should be created for the corresponding Planer Role depending to the maintained regional center to inform about the failed validations, so the responsible Planer group has the possibility to correct the data in EAM and then can decide:  1. If the EAM Transfer should be restarted, after the structure was corrected in EAM → option "Retry EAM Transfer" 2. If the device data was added manually, so the EAM Transfer could be skipped → option "Station data updated manually in EAM - skip EAM Transfer" |
| **Permissions** | Role Planer DigiONS \<RZ\> |
| **Preconditions** | [(17) Transfer to EAM](https://eon-energy.atlassian.net/wiki/spaces/kfwt22/pages/880247612/17+Transfer+to+EAM) with a failed validation in regards to the EAM structure |
| **State** | IN REFINEMENT |
